2. Repaso rápido de conceptos clave

Sesión 5 (9 oct) — Introducción a DRF

✓DRF se instala con pip install djangorestframework y se registra como 'rest_framework' en INSTALLED_APPS.
✓DRF resuelve el problema de exponer los modelos de Django como JSON consumible por cualquier cliente (app móvil, frontend, etc.), en lugar de HTML.
✓La Browsable API es la interfaz navegable que DRF genera automáticamente para probar los endpoints desde el navegador.

Sesión 6 (14 oct) — Serializers

✓Un ModelSerializer traduce entre un modelo y JSON, generando los campos automáticamente a partir de Meta.model y Meta.fields.
✓Serializar es modelo → JSON (serializer.data); deserializar es JSON → datos validados de Python (is_valid(), save()).
✓Las validaciones personalizadas se escriben con validate_<campo> (un campo) o validate (varios campos a la vez).

Sesión 7 (15 oct) — ViewSets y Routers

✓Un ModelViewSet agrupa listar, crear, ver detalle, actualizar y borrar en una sola clase, a partir de queryset y serializer_class.
✓Un DefaultRouter genera automáticamente las URLs del CRUD al registrar el ViewSet con router.register().
✓PUT actualiza el recurso completo; PATCH permite actualizar solo algunos campos.

4. Ejercicio integrador paso a paso

Vamos a exponer como API completa el sistema de "Biblioteca" construido entre las sesiones 1 y 4, combinando los tres temas de este bloque. Sigue los pasos en orden:

Paso 1: Instalación y configuración (repaso sesión 5)

pip install djangorestframework

Agrega 'rest_framework' a INSTALLED_APPS.

Paso 2: Serializers (repaso sesión 6)

En biblioteca/serializers.py:

from rest_framework import serializers
from .models import Autor, Libro

class AutorSerializer(serializers.ModelSerializer):
    class Meta:
        model = Autor
        fields = ['id', 'nombre', 'nacionalidad']

class LibroSerializer(serializers.ModelSerializer):
    autor_nombre = serializers.CharField(source='autor.nombre', read_only=True)

    class Meta:
        model = Libro
        fields = ['id', 'titulo', 'autor', 'autor_nombre', 'precio', 'disponible', 'fecha_publicacion']

    def validate_precio(self, value):
        if value <= 0:
            raise serializers.ValidationError("El precio debe ser mayor que cero.")
        return value

Paso 3: ViewSets y Router (repaso sesión 7)

En biblioteca/views.py:

from rest_framework import viewsets
from .models import Autor, Libro
from .serializers import AutorSerializer, LibroSerializer

class AutorViewSet(viewsets.ModelViewSet):
    queryset = Autor.objects.all()
    serializer_class = AutorSerializer

class LibroViewSet(viewsets.ModelViewSet):
    queryset = Libro.objects.all().order_by('titulo')
    serializer_class = LibroSerializer

En biblioteca/urls.py:

from rest_framework.routers import DefaultRouter
from django.urls import path, include
from . import views

router = DefaultRouter()
router.register('autores', views.AutorViewSet, basename='autor')
router.register('libros', views.LibroViewSet, basename='libro')

urlpatterns = [
    path('resumen/', views.resumen, name='resumen'),
    path('', include(router.urls)),
]

Paso 4: Verificación end-to-end

Levanta el servidor y, desde la Browsable API en /biblioteca/libros/, realiza en orden: un GET de listado, un POST de creación con un precio inválido (debe fallar por la validación), un POST válido, un PATCH sobre el registro creado y un DELETE final.

5. Errores comunes del bloque (repaso general)
✗Olvidar registrar rest_framework en INSTALLED_APPS → la Browsable API no se ve estilizada o falla.
✗Exponer todos los campos del modelo con '__all__' sin revisar si alguno debería quedar oculto.
✗Olvidar basename en router.register() cuando el ViewSet sobreescribe get_queryset().
✗Confundir PUT (todos los campos) con PATCH (campos parciales) y recibir errores de validación inesperados.
✗Llamar serializer.save() sin haber llamado antes a is_valid().
