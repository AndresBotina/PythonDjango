1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de crear un ModelViewSet a partir de un modelo y su serializer, conectar ese ViewSet a un Router para generar automáticamente las URLs de un CRUD completo, y explicar la diferencia entre escribir vistas una por una y usar un ViewSet.

2. De la vista de función al ViewSet

La sesión 5 escribimos una función con @api_view que solo sabía hacer una cosa: listar. Si quisiéramos también crear, actualizar y borrar libros, tendríamos que escribir y conectar manualmente cuatro o cinco vistas distintas, cada una con su propia ruta en urls.py.

Un ViewSet agrupa toda esa lógica CRUD (listar, crear, ver detalle, actualizar, borrar) en una sola clase. Y un ModelViewSet va un paso más allá: si le pasamos un queryset y un serializer_class, genera automáticamente las cinco operaciones sin que tengamos que escribir el código de cada una.

💡 Idea clave
ModelViewSet + Router es la combinación que verás en la inmensa mayoría de proyectos DRF en el mundo real para CRUDs estándar. Solo cuando necesitamos lógica muy particular volvemos a las vistas más manuales (APIView, que veremos en la sesión 9).
3. Creación de un ModelViewSet

En biblioteca/views.py, usando el serializer de la sesión anterior:

from rest_framework import viewsets
from .models import Autor, Libro
from .serializers import AutorSerializer, LibroSerializer

class AutorViewSet(viewsets.ModelViewSet):
    queryset = Autor.objects.all()
    serializer_class = AutorSerializer

class LibroViewSet(viewsets.ModelViewSet):
    queryset = Libro.objects.all().order_by('titulo')
    serializer_class = LibroSerializer

Con estas dos clases, cada ViewSet ya sabe responder a las siguientes acciones, sin una sola línea adicional:

Verbo HTTPURLAcción
GET/libros/Listar todos los libros
POST/libros/Crear un libro nuevo
GET/libros/{id}/Ver el detalle de un libro
PUT / PATCH/libros/{id}/Actualizar un libro (completo / parcial)
DELETE/libros/{id}/Eliminar un libro
4. Conectar el ViewSet con un Router

El Router es quien traduce el ViewSet en las URLs de la tabla anterior. Crea o reemplaza biblioteca/urls.py:

from django.urls import path, include
from rest_framework.routers import DefaultRouter
from . import views

router = DefaultRouter()
router.register('autores', views.AutorViewSet, basename='autor')
router.register('libros', views.LibroViewSet, basename='libro')

urlpatterns = [
    path('resumen/', views.resumen, name='resumen'),
    path('', include(router.urls)),
]

Recuerda que config/urls.py (el del proyecto) ya incluye las rutas de la app desde la sesión 1:

urlpatterns = [
    path('admin/', admin.site.urls),
    path('biblioteca/', include('biblioteca.urls')),
]

Con esto, visitando http://127.0.0.1:8000/biblioteca/libros/ tendrás el listado y creación de libros, y http://127.0.0.1:8000/biblioteca/libros/1/ el detalle, actualización y borrado del libro con id 1. El DefaultRouter además genera una página raíz de la API en /biblioteca/ con enlaces a todos los recursos registrados.

5. Ejercicio práctico (para hacer en clase)
  1. Crea un ModelViewSet para cada uno de tus modelos principales, usando los serializers de la sesión anterior.
  2. Registra ambos ViewSets en un DefaultRouter dentro de urls.py de tu app.
  3. Verifica en el navegador que la ruta raíz del router (ej. /api/) muestre los enlaces a tus recursos.
  4. Desde la Browsable API, crea un registro nuevo usando el formulario HTML que DRF genera automáticamente al final de la página de listado.
  5. Desde la Browsable API, entra al detalle de un registro y pruébalo con el método PATCH para actualizar solo un campo.
  6. Elimina un registro usando el botón DELETE de la Browsable API y confirma que desaparece del listado.
  7. Explica en un comentario dentro de tu código qué diferencia práctica hay entre usar PUT y usar PATCH.
6. Errores comunes
✗Olvidar basename en router.register() cuando el ViewSet no define queryset a nivel de clase (por ejemplo, si se sobreescribe get_queryset()) → error al iniciar el servidor.
✗Registrar el mismo prefijo dos veces en el router → una de las rutas queda inaccesible.
✗Olvidar include(router.urls) en urlpatterns → todas las rutas del router responden 404.
✗Confundir PUT (requiere enviar todos los campos) con PATCH (permite enviar solo los campos a modificar) y recibir errores de validación por campos "faltantes".
